I checked the repo again after the latest prompt. I’m going to be blunt: the implementation is still not where I want it, and I would not freeze Phase 1 yet.

The good part is that the architecture has improved in one important way: the 3D scene is now scoped inside the sticky hero rather than mounted as a fixed background across the entire landing page. HeroSection.jsx now uses a 400vh hero with a sticky 100vh scene. That is the right architectural direction.

But the actual 3D implementation still has several problems.

But here is the major problem
❌ The "Earth" is still procedurally generated noise

The current shader says:

float n = snoise(vWorldPosition * 0.8) * 0.5 + 0.5;
n += snoise(vWorldPosition * 2.0) * 0.25;

and then:

vec3 oceanColor = vec3(0.01, 0.01, 0.02);
vec3 landColor = vec3(0.02, 0.04, 0.08);

That does not create Earth geography.

It creates procedural noise and thresholds it.

So Antigravity technically followed the instruction "create continents procedurally," but the result is fundamentally the wrong visual approach.

That's why you're getting the ugly glowing blob.

We need an actual geographic silhouette.

Not noise.

Not a wireframe.

Not a sphere pretending to be Earth.

❌ The Earth shader is also causing the cyan blowout

The shader has:

vec3 atmosphereColor = vec3(0.0, 0.6, 0.8) * intensity;

combined with:

float intensity = pow(rim, 3.0) * 1.5;

That can produce the huge cyan halo you showed me.

The result is exactly what we told Antigravity not to create:

giant glowing cyan sphere.

So this isn't something I would fix by tweaking 0.6 → 0.3.

The material strategy needs changing.

❌ The network is still too simplistic

Right now we have only:

PHISHING
   ↓
WEBSITE
   ↓
IDENTITY
   ↓
AUTH

That's not inherently bad, but it's currently just a chain.

Our intended visual was closer to:

                 MEDIA
                   │
                   ▼
PHISHING ─── WEBSITE ─── IDENTITY
                   │          │
                   ▼          ▼
              TECHNICAL   AUTHENTICATION

The network needs branching relationships, otherwise the globe doesn't visually demonstrate correlation intelligence.

❌ More importantly: the network isn't really animated as a network

The code fades connections:

child.material.opacity += (...)

but there's no proper signal travelling along the connection.

We explicitly wanted:

● ───────────────→ ●
       •
    travelling
     signal

That little travelling particle is important.

It makes the connection feel like information moving, not just a line appearing.

❌ The HUDs are still DOM hacks inside the 3D scene

For example:

document.getElementById(`hud-${nodeIdx}`)

and:

document.getElementById('hud-evidence')

inside useFrame.

This works, but I don't like this architecture.

useFrame() running every render frame should not repeatedly manipulate DOM elements with getElementById.

We should eventually move this to React state / derived animation state or use Drei's <Html> with controlled props.

It's not the biggest visual problem right now, but it's something I'd clean before calling this production-quality.

❌ The camera implementation has a bug in its design

They do:

camera.position.lerpVectors(startCam, endCam, progress);

then immediately:

camera.position.x += ...
camera.position.y += ...

So they're mixing direct interpolation and another interpolation mechanism.

That's likely to produce less predictable motion.

We should have a clean camera timeline:

progress
   ↓
camera position
camera target
camera FOV
globe scale
network scale

all derived from the same timeline.

❌ We don't actually have the "VEILLE-level" cinematic transition yet

This is the most important part.

Right now the experience is essentially:

Scroll → camera moves closer → objects fade in/out.

What we want is:

Scroll → the meaning of the scene changes.

That's a much higher bar.
